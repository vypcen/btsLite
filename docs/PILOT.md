# Пилот BlackCat Testing Community: план на 3–4 недели

Цель пилота — на реальном проекте и реальной команде проверить, что BlackCat Testing заменяет текущий инструмент (TestRail, Test IT, Excel, Jira + плагин) и что команде в нём удобно работать.

## Кто участвует

| Роль | Кто | Задача на пилоте |
|---|---|---|
| Владелец пилота | руководитель тестирования | цели, итоговое решение |
| Администратор | DevOps или сисадмин | установка, локальные учётные записи, резервные копии |
| Команда | до 4 тестировщиков при одном администраторе, разработчики | ежедневная работа |
| Поставщик | менеджер и инженер BlackCat Testing | помощь, исправления, еженедельные встречи |

## Неделя 0. Подготовка (1–2 дня)

- [ ] Сервер: 2 ядра, 4 ГБ, 20 ГБ диска, Docker. Установка по [README, часть 1](../README.md#часть-1-развернуть-на-своём-компьютере) — около часа.
- [ ] HTTPS-адрес внутри сети компании, `PUBLIC_URL`, `REGISTRATION=closed`.
- [ ] До пяти активных пользователей на пилот, включая разработчиков и наблюдателей.
- [ ] Локальные учётные записи и двухфакторная аутентификация.
- [ ] Резервное копирование по расписанию (`scripts/backup.sh`).
- [ ] Перенос данных одного проекта: импорт из TestRail / TestLink / Qase или CSV ([руководство администратора](ADMIN_GUIDE.md#перенос-данных-из-других-систем)).
- [ ] Подключение трекера (Jira, YouTrack, GitLab, Redmine) и одного пайплайна автотестов.
- [ ] Вводная встреча с командой на 1 час: [руководство пользователя](USER_GUIDE.md), разделы «Основные понятия» и «Прогоны».

## Неделя 1. Ручное тестирование

Команда ведёт новые кейсы и проводит прогоны только в BlackCat Testing.

- [ ] Кейсы со структурными шагами, папки, теги, пользовательские поля, если они нужны процессу.
- [ ] Тест-план регресса (статический или динамический) и прогон по нему на текущей сборке.
- [ ] Баги заводятся из упавших шагов и уходят в трекер.
- [ ] Распределение кейсов между исполнителями.

## Неделя 2. Автотесты и требования

- [ ] Результаты автотестов из CI приходят в BlackCat Testing (Playwright, JUnit XML или Allure), токен — от пользователя-робота.
- [ ] Автотесты связаны с ручными кейсами.
- [ ] Требования релиза импортированы из Jira/CSV и связаны с кейсами; покрытие видно на вкладке «Требования».
- [ ] Нестабильные автотесты видны в «Аналитике».

## Неделя 3. Отчётность и релиз

- [ ] Релизный регресс целиком в BlackCat Testing.
- [ ] Отчёт по прогону и тест-плану (PDF/Excel) отправлен руководителю, матрица трассировки — заказчику или аналитику.
- [ ] Руководитель видит прогресс без вопросов команде.
- [ ] Проверено восстановление из резервной копии на отдельном стенде.

## Неделя 4. Итоги

Встреча владельца пилота, команды и поставщика: метрики, опрос, список доработок, решение.

## Критерии успеха

Согласуйте до старта и заполните в конце:

| Критерий | Цель | Факт |
|---|---|---|
| Доля прогонов пилотного проекта, проведённых в BlackCat Testing | ≥ 90% | |
| Время подготовки отчёта по релизу | в 2 раза меньше, чем сейчас | |
| Баги из прогонов попадают в трекер без ручного копирования | да | |
| Результаты автотестов видны рядом с ручными | да | |
| Покрытие требований тестами видно без Excel | да | |
| Оценка удобства командой (опрос, 1–5) | ≥ 4 | |
| Критичные ошибки системы, блокирующие работу | 0 | |
| Потерянные данные | 0 | |

## Как собирать обратную связь

- Общий чат пилота с поставщиком; ответ в рабочее время — в течение 4 часов.
- Ошибку присылайте с текстом кнопки «Скопировать для поддержки» («Пользователи» → «Лицензия и система»), шагами и скриншотом.
- Пожелания — одной таблицей: что нужно, зачем, насколько мешает без этого (блокирует / неудобно / хотелось бы).
- Короткий опрос команды в конце недель 1 и 3: что удобнее, чем раньше; что неудобнее; чего не хватает.

## После пилота

- **Решение «да»:** обсудите переход на Enterprise и перенос проектов.
- **Решение «нет»:** выгрузка всех проектов в JSON или CSV («Настройки» → «Скачать со всеми вложениями»), удаление стенда. Данные остаются у вас.
